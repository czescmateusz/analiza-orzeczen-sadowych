# App prototype: "Czy oferta ubezpieczyciela jest uczciwa?"

A static site: plain HTML, CSS and JavaScript, with no build step and no backend. Everything the
user enters stays in their browser. The data in `data/` is generated by `orzeczenia export`.

## Run locally

From the repository root:

```
.venv/Scripts/python scripts/serve.py      # http://127.0.0.1:8765, no browser caching
```

(`python -m http.server` works too, but the browser may then keep old copies of the JavaScript
files after a change; press Ctrl+F5.)

Then open http://127.0.0.1:8765. Opening `index.html` directly from disk (`file://`) doesn't work,
because the browser blocks `fetch()` of the data files.

To open a pre-filled example, put the parameters after `#`, for example
http://127.0.0.1:8765/#rola=p&kat=noga&u=10&wiek=35&okol=dlugie_leczenie&oferta=15000
or http://127.0.0.1:8765/#rola=b&rel=rodzic&oferta=50000.

| Parameter | Meaning |
|---|---|
| `rola` | `p` injured person, `b` relative after a death |
| `kat` | Injury categories, comma-separated (ids in `data/labels.json`) |
| `u` | % uszczerbku |
| `wiek` | Age |
| `rel` | Relation: `rodzic` (a child died), `malzonek`, `dziecko` (a parent died), `rodzenstwo`, `inny` |
| `okol` | Factors, comma-separated |
| `oferta` | The insurer's offer in zł |
| `od` | Count judgments from this year (any year 2004–2026) |
| `ceny=nom` | Nominal amounts (default: converted to the latest full year's prices with GUS's CPI) |
| `rola=pb` | Both situations: injured, and a close person died. Use `oferta`/`okol`/`wiek` for the injury claim and `oferta_b`/`okol_b`/`wiek_b`/`rel` for the death claim |

The fragment after `#` is never sent to the server.

## Refresh the data

```
.venv/Scripts/orzeczenia export      # writes app/data/ (~95 MB: cases, citations, quotes, parser browser and its index)
.venv/Scripts/orzeczenia model       # writes app/data/model.json (statistical model, n-grams, trend)
```

## Pages

- `index.html`: compare an insurer's offer with court totals in similar cases.
- `przegladarka.html`: search all judgments and see what the parser read from each, with
  source sentences. Filters live in the URL, e.g. `przegladarka.html#q=kołnierza&role=p`
  or `#j=456035` for one judgment.
- `metodologia.html`: sample, assumptions, statistical model, keywords and n-grams, time trend.
  It reads `data/model.json`, which `orzeczenia model` writes (needs the `analysis` extra).

## Files

- `logic.js`: matching and statistics (pure functions; tested in `tests/test_app_logic.py`
  through QuickJS, so Node isn't needed).
- `app.js`: form, results, chart, quotes.
- `style.css`: mobile-first, light and dark mode.

## Deploy

Upload the `app/` folder as is to Cloudflare Pages (or GitHub Pages). No build command is needed.
